# M4: training sessions in the app — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Before starting, apply the roadmap's refresh rule** (re-read against `docs/measurements.md`, update numbers here in a commit).

**Goal:** Peter starts an 8-hour training session from the app before school, with a planned end time, and comes back to a useful summary.

**Architecture:** `ofai.sessions.SessionManager` (inside the service) runs each session as a child process (`python -m ofai bc|rl --until ...`) so the service stays responsive, reattaches to it after a service or app restart, and controls it through a `CONTROL` file the trainer polls (pause, shrink workers, stop). At the end the trainer reserves time for a `bench-v1` run and writes `summary.json`. The app gets Home, Train and Models screens and a one-double-click launcher.

**Tech Stack:** Python service (M1), React app (M1), the `dataviz` skill for charts.

**Spec:** §4 (sessions), §13 (sharing one PC, sessions), §16 (Home, Train, Models; one double-click), §18 (M4).

## Global Constraints

All of roadmap §2. Most relevant: sessions use all cores but 2; checkpoints atomic; UI loads the `frontend` skill; charts load the `dataviz` skill.

## Review Focus

1. **PC rebooted (Windows Update) mid-session**: on next app start the session shows "interrupted at <time>" with **Resume** (resumes from the latest valid checkpoint to the same planned end, or a new one) (Task 1 test `interrupted session offers resume`).
2. **Planned end earlier than now + bench time**: start is refused with a clear message (Task 1 test `end too soon is refused`).
3. **Session process crashes**: state `failed`, last 40 stderr lines and the last `error` event shown in Train (Task 1 test `crash keeps stderr tail`).
4. **Disk nearly full** (records + checkpoints + replays): the trainer keeps only the newest 5 checkpoints of a run plus any registered ones, and warns under 10 GB free (Task 2 test `checkpoint retention`).
5. **App closed during a session**: the session keeps running (it is not a child of the Electron process tree), and the next app start reattaches (Task 1 test `service restart reattaches`).

### Task 1: SessionManager

**Files:** Create `learn/ofai/sessions.py`, `learn/tests/test_sessions.py`; Modify `learn/ofai/service/app.py`.

**Interfaces:**
- Produces:
  - `@dataclass SessionSpec(phase: "bc"|"rl", config: str, until: datetime, resume: str | None = None, bench_minutes: int = 60, workers: int | None = None /* default cpu_count - 2 */)`
  - `class SessionManager(state_file: Path = DATA / "sessions.json")`: `start(spec) -> Session`, `stop(id)`, `pause(id)`, `resume_paused(id)`, `set_workers(id, n)`, `reattach() -> list[Session]`, `list() -> list[Session]`.
  - `Session = {"id", "runDir", "phase", "state": "running"|"paused"|"stopping"|"done"|"failed"|"interrupted", "pid", "startedAt", "until", "workers", "error", "stderrTail"}`.
  - Child process started detached (Windows `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS`; POSIX `start_new_session=True`), stdout/stderr to `runDir/stdout.log`.
  - `CONTROL` file contract (read by `train_bc`/`train_rl` between updates): `{"pause": bool, "workers": int, "stop": bool}`; the trainer acknowledges with an `events.jsonl` line.
  - Service endpoints: `POST /sessions`, `GET /sessions`, `POST /sessions/{id}/stop|pause|resume`, `POST /sessions/{id}/workers`.
- [ ] Failing tests: `start writes state and runs child`, `end too soon is refused`, `stop writes CONTROL and waits`, `crash keeps stderr tail`, `service restart reattaches`, `interrupted session offers resume` (state has pid that is gone and `until` in future → `interrupted`).
- [ ] Run → FAIL. Implement. Run → PASS. Modify `train_bc` (M3) to honour `CONTROL`, with a test `control pause stops consuming the stream`. Commit `"learn: training sessions with reattach and control file"`.
