# OpenFront AI v3: implementation roadmap

> **For agentic workers:** this file is the index. Each milestone has its own plan file below; execute one milestone plan at a time with superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Every milestone plan assumes this file's **Global Constraints** and **Shared Contracts**.

**Goal:** build the v3 OpenFront AI from an empty repo to a model that plays public FFA lobbies at a skilled-human level, one watchable milestone at a time.

**Architecture:** a git-submodule engine plus a per-commit build cache (`engines/<commit>/`); a TypeScript `sim/` package that is the only code touching the engine (replay, encoder, action codec, translator, multi-seat env, headless client); a Python `learn/ofai` package (crawler, data index, model, imitation, PPO, league, benchmarks, inference service); one Electron `app/` over both.

**Tech stack:** Node 24 + TypeScript + vitest + esbuild (sim); Python 3.11 + PyTorch 2.8 CUDA 12.8 + pytest + FastAPI/uvicorn (learn); Electron + Vite + React + TypeScript (app); SQLite (data index).

**Spec:** [`docs/superpowers/specs/2026-11-14-v3-design.md`](../specs/2026-11-14-v3-design.md). Section numbers like §9.3 refer to it.

## 2. Global Constraints

Every task in every milestone implicitly includes these.

- **License:** AGPL-3.0 (repo root `LICENSE`). Engine is `openfrontio/OpenFrontIO`.
- **Platforms:** everything runs on Windows 11 (16 cores, RTX 3060 Ti 8 GB). `sim/` and `learn/` must also run headless on Linux + CUDA (no app). Paths via `path.join` / `pathlib`, never hard-coded separators.
- **Crawling:** at most **1 request/s** across the whole crawler; exponential backoff on 429/5xx (start 2 s, cap 120 s, honour `Retry-After`); User-Agent exactly `ofai-crawler/0.1` (no personal data, no email); stop and surface an error if the API returns 403.
- **Human checks:** no code anywhere solves, bypasses, scripts or hides from a captcha or any human check. A human always passes them.
- **AI identity:** in games we construct (env, bench), every AI player name starts with `[AI] `. When an AI joins through the game's own protocol (local or online), it joins with clan tag `AI`, which the game renders as `[AI] name` (the engine's `ClanTagSchema` is `^[a-zA-Z0-9]{2,5}$`, and the clan tag is the game's own way to show a tag). Never without the tag.
- **Online code:** nothing that connects to openfront.io game servers lives in this repo. Only local (dev-server) transport here (§17).
- **Checkpoints and data:** `data/`, `runs/`, `checkpoints/`, `engines/`, `replays/` are gitignored and never committed. No real game records committed as fixtures (they hold usernames): tests use synthetic records produced by our own engine runs, and real-record tests read `data/records/` and skip when it is empty.
- **Determinism:** a replayed record must match its hash at every turn that carries one (every 10 turns). Any mismatch rejects the whole game.
- **Version window:** default = commits seen in records whose game started in the last **21 days**, capped to the **10** most recently first-seen commits.
- **Data filter:** `type == Public`, mode FFA, duration ≥ **300 s**, no special modifiers, `gitCommit` in the window.
- **Timing:** decision step every **5 turns** (0.5 s); up to **K = 4** actions per step, ending in STOP. Self-play applies a step's intents after a random **1–3 turn** delay.
- **Arguments:** troop fraction in **20 buckets of 5 %**; minimap **128×128**; up to **8** zoom windows of **32×32** cells at **2–4 tiles per cell**; **32** player tokens + 1 "rest" + 1 "unowned land".
- **Model:** LSTM core width **512**; total **10–15M** parameters on the 3060 Ti; plain PyTorch checkpoints.
- **Reward (M6):** final placement + win bonus + at most **one** potential-based land-share term. A new term needs a benchmark A/B.
- **Sessions:** use all CPU cores but **2**; write checkpoints atomically (temp file + rename).
- **Benchmarks:** `bench-v1` frozen at M3; never edited after freezing; a change means `bench-v2`.
- **Git:** author email `nagy.peter.zalan@gmail.com`; commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` when written by Claude; never "🤖 Generated with Claude Code" in commits. One PR per milestone.
- **UI:** any app screen work loads the `frontend` skill before writing UI code.

### 3.2 Engine bundles

`BundleMeta` (`engines/<commit>/meta.json`), written by `ofai.engines`:

```json
{"commit": "<40-hex>", "status": "ok" | "failed", "stage": "fetch" | "worktree" | "deps" | "bundle" | "selfcheck" | null,
 "error": "<message or null>", "builtAt": "<ISO-8601>", "lockHash": "<sha256 of package-lock.json>",
 "simVersion": "<sim/package.json version>", "layoutVersion": <int>}
```

Dependency rule: every worktree gets a `node_modules`. When its `package-lock.json` hash equals `engine/`'s, `engines/<commit>/src/node_modules` is a directory junction (Windows) / symlink (Linux) to `engine/node_modules`; otherwise `npm ci --ignore-scripts` runs in the worktree. Both the esbuild bundle and the commit's own dev server (M1 replay viewer) then resolve packages normally.

### 3.4 Bridge protocol v3

Framing (both directions, local TCP, little endian), unchanged from v2: `[u32 payloadLen][u32 seq][u8 msgType][body]`. Client numbers requests from 1; replies echo the seq; HELLO is seq 0; a seq mismatch is fatal.

| Type | Dir | Body |
|---|---|---|
| `0x10 HELLO` | s→c | JSON `{protocol: 3, layoutVersion, role, rows}` |
| `0x01 RESET` | c→s | JSON `{games: GameSpec[]}` (env role, M2) |
| `0x02 STEP` | c→s | `[u32 rows][i32 rows×K×A actions]` (env role) |
| `0x04 LOAD` | c→s | JSON `{records: {path, teachers: string[]}[]}` (replay role, M2) |
| `0x05 NEXT` | c→s | empty (replay role: advance one decision step) |
| `0x06 ACT` | c→s | `ObsBlock` + per-row `seatKey` (JSON array), `checkpoint` name, `fresh u8` (inference service, M5) |
| `0x03 CLOSE` | c→s | empty |
| `0x11 ROWS` | s→c | `ObsBlock` + per-row `reward f32, flags u8, stats f32×5, terminal u8` (env) |
| `0x12 SAMPLES` | s→c | `ObsBlock` + per-row `labels i32×K×A, weight f32, value f32, flags u8` (replay) |
| `0x13 ACTIONS` | s→c | `i32 rows×K×A` actions + JSON mind lines per row (inference service, M5) |
| `0xFF ERROR` | s→c | `[u8 code][utf8 message]`, then disconnect |

`flags` bits: 0 VALID (row has data), 1 DONE (row's game/episode ended this step), 2 NEXT (row acts next step), 3 FRESH (obs belongs to a new game; reset LSTM state). `ObsBlock` is defined by the layout (3.5) and serialized field by field in layout order.

### 3.5 Observation on the wire (compact) and on the GPU (planes)

Decision (refines §9 with measured bandwidth): planes are **not** sent. 31 u8 planes at 128×128 plus 8 windows is ~760 KB per sample, which at the ~1,200 samples/s the 3060 Ti can train on is ~900 MB/s. Instead the sim sends compact per-game rasters and per-seat perspective, and `ofai.model.planes.expand()` builds the planes on the GPU. about 60 KB per sample (measured in M2 Task 12).

Per game (shared by its seats): `mm_owner u16[128,128]` (0 unowned, 0xFFFF outside the map, else owner smallID), `density f16[1024]` (troops ÷ tiles per smallID, normalized; OpenFront troops belong to a player, not a tile, so density planes are owner raster × this vector), `mm_terrain u8[128,128]` (bits: land, coast, shore-water, highland, mountain), `units i32[1024,6]` (type, ownerSmallID, x, y, level, flags; type −1 = empty), `game_meta f32[8]` (map w, h, minimap tiles-per-cell, ticks, spawn phase, ...).

Per seat: `relation u8[1024]` (relation code per smallID: 0 none, 1 self, 2 ally, 3 neutral, 4 they attack us, 5 we attack them, 6 both), `win_meta f32[8,6]` (x0, y0, tiles-per-cell, kind, valid, priority), `win_owner u16[8,32,32]`, `win_terrain u8[8,32,32]`, `players f16[34,PF]`, `edges f16[34,34,EF]`, `structs f16[64,SF]`, `mobile f16[32,MF]`, `attacks f16[32,AF]`, `globals f32[GF]`, `type_mask u8[17]`, `build_mask u8[10]`. Index 32 of `players` is the pooled rest, 33 is "unowned land".

`PF`, `EF`, `SF`, `MF`, `AF`, `GF` and the plane list are fixed in M2 Task 1 (`sim/src/obs/Layout.ts`), exported by `sim.mjs layout`, and read by `ofai.layout` at HELLO. Python never hard-codes them.

### 3.6 Actions and labels

One action = `i32[A=10]`: `type, player, entity, build, troops, locMode, window, cell, mmCell, fine` (−1 = unused). A step = `K=4` actions; after the first STOP the rest are −1.

| type | name | uses |
|---|---|---|
| 0 | STOP | – |
| 1 | SPAWN | loc |
| 2 | ATTACK | player (0–31 or 33 = unowned), troops |
| 3 | BOAT | loc, troops |
| 4 | BUILD | build, loc |
| 5 | UPGRADE | entity (structs) |
| 6 | MOVE_WARSHIP | entity (mobile), loc |
| 7 | CANCEL_ATTACK | entity (attacks) |
| 8 | CANCEL_BOAT | entity (mobile) |
| 9 | ALLIANCE_REQUEST | player |
| 10 | ALLIANCE_REJECT | player |
| 11 | ALLIANCE_EXTEND | player |
| 12 | BREAK_ALLIANCE | player |
| 13 | TARGET_PLAYER | player |
| 14 | EMBARGO_START | player |
| 15 | EMBARGO_STOP | player |
| 16 | DELETE_UNIT | entity (structs or mobile; structs first, mobile at offset 64) |

`build`: 0 city, 1 port, 2 factory, 3 defense post, 4 SAM launcher, 5 missile silo, 6 warship, 7 atom bomb, 8 hydrogen bomb, 9 MIRV. `troops`: bucket b means (b+1)×5 % of current troops. `loc`: `locMode` 0 = near (`window` 0–7, `cell` 0–1023 = row×32+col), 1 = far (`mmCell` 0–16383 = row×128+col, `fine` 0–255 = 16×16 grid over that minimap cell's tile span).

## 4. Review Focus (cross-milestone)

The failure modes the spec implies but no single test covers. Each line names the task that pins it.

1. **A commit whose bundle fails, or a record with an intent type our adapter doesn't know**: the record is dropped and counted, the batch continues (M0 Task 5, M1 Task 3).
2. **Extreme maps** (512×512; 4432×2528; portrait 2036×4428; windows touching map edges): encoder never reads out of bounds, letterbox marked invalid (M2 Tasks 2–3).
3. **A teacher who dies, disconnects, or never spawns**: their rows go invalid from that step; the game keeps replaying for the other teachers (M2 Task 6).
4. **App closed or crashed while children run** (game dev server on 9000 and its server process, Python service on 47800, sim workers): next start finds and stops orphans before binding (M1 Task 7).
5. **Power loss mid-checkpoint**: a half-written checkpoint is never picked as the latest (M3 Task 7).
